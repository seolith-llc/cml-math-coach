## Request (verbatim)

> add a parent dashboard to track my kid's progress

## Response summary

**Decision (asked the user):** a dashboard you can open from any device, synced to the cloud. Chosen over an iPad-only, PIN-locked view.

**Architecture**
- **Storage:** Cloudflare D1, schema in `migrations/0001_parent_dashboard.sql`.
  - `families`: hashed family key, PBKDF2 PIN hash, child name and grade, snapshot JSON, lockout fields.
  - `attempts`: one row per answered problem.
- **API:** `server/parent.ts`, wrapped by `functions/api/sync.ts` and `functions/api/parent.ts`.
  - Sync needs the 144-bit family id; read and delete need the family id plus the PIN.
  - Only sha256 of the id is stored. 5 wrong PINs lock the family for 15 minutes.
  - Same-origin only. Inputs are clamped, and attempts are deduplicated by primary key.
- **Client:**
  - The device now keeps an attempt log (4,000 cap) with level, first-try flag, hints, seconds, first wrong answer and mode.
  - `src/sync/sync.ts` uploads new attempts in batches. It is debounced 4 s after each answer, sends a beacon when the app is hidden, retries when back online, and is offline-first.
- **Kid Settings:** a "Parent dashboard" card to set the PIN, share/copy the private link, sync now, and turn off with deletion.
- **Dashboard** (`#/parent/<id>`, `src/ui/parent.ts`):
  - PIN gate (kept for the tab session only).
  - KPI tiles comparing this week with last week (problems, first-try %, minutes, days, streak) and the review backlog.
  - Plain-language suggestions.
  - 30-day stacked daily chart (first try vs needed help; palette validated with the dataviz validator for light and dark).
  - Topic table: practiced topics by category with a mastery meter and status (⚠️ needs help / 🌱 building / ⭐ strong); untried topics collapsed.
  - Mock meet score chart.
  - Recent mistakes, regenerated from problem ids: the question, the child's answer and the correct answer.
  - CSV export and Lock.
- **CI:** `scripts/ensure-d1.mjs` creates the D1 database if missing, applies the migrations idempotently, and binds `DB` at deploy. It needs the token permission **Account → D1 → Edit**; without it, the deploy warns and continues.
- "Reset progress" now keeps the sync link, so the online copy isn't orphaned.
