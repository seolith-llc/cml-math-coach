## Request (verbatim)

> This app should be completely not searchable and accessible over the internet or for agents

## Response summary

**Layer 1, live and verified by the Status probe from GitHub Actions**
- `robots.txt` disallows everything.
- Every response carries `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet, noimageindex, notranslate` (via `_headers` and the middleware), and the page has a robots meta tag.
- `functions/_middleware.ts` → `server/guard.ts` refuses (403):
  - search crawlers;
  - AI crawlers, assistants and agents;
  - link-preview, SEO and archive bots;
  - headless automation.
- Browsers and our CI tools still get through.
- The production probe confirmed it: all 8 sample crawler and agent identities got 403, and the app and API still worked.
- `tests/guard.test.ts` covers it.

**Layer 2: Cloudflare Access.** The owner chose it over a built-in sign-in or a shared passcode, and kept the repo public.
- `scripts/cloudflare-access.mjs` + `.github/workflows/cloudflare-access.yml` (manual, idempotent):
  - checks Zero Trust is set up and enables the one-time PIN email login;
  - creates or updates the "Math Coach" app on the custom domain, `cml-math-coach.pages.dev` and every preview, with a 30-day session;
  - policies: invited emails (from the secret `ACCESS_ALLOWED_EMAILS`, never in public logs) and the CI service token `math-coach-ci`;
  - a bypass app only for `/api/email/confirm` and `/api/email/unsubscribe` (token-protected; keeps one-click unsubscribe working);
  - verifies live that a stranger gets the sign-in page on both hosts, the API is unreachable, the service token gets in, and email links skip sign-in.
- **CI is ready before Access is turned on:** the deploy smoke tests, domain check, hourly job and Status probe send the Access service-token headers when the secrets exist. The probe adds an Access check.

**Owner actions** (docs/DEPLOY.md, "Private access")
1. Set up Zero Trust (team name, Free plan).
2. Create the service token `math-coach-ci` and add the secrets `CF_ACCESS_CLIENT_ID/SECRET`.
3. Add the Access permissions to the API token (or a new `CLOUDFLARE_ACCESS_TOKEN`).
4. Add the secret `ACCESS_ALLOWED_EMAILS`.
5. Run Actions → Cloudflare Access.
