## Request (verbatim)

> We need to have a feedback/suggestion button in the app itself to capture and work on them after triaging

## Response summary

**Design decision:** this repository is public, so feedback is **not** turned into GitHub issues, and message text never appears in Actions logs. A message from a parent can mention a child. Messages are stored privately in D1 and emailed to the owner.

**App**
- A speech-bubble **Feedback** button in the top bar, next to Settings (hidden on the parent dashboard).
- `src/ui/feedbackSheet.ts`: a native `<dialog>` with **Problem / Idea**, a message and Send. "Problem" is preselected when a problem is on screen.
- The screen, the problem on screen (new `data-problem-id` on problem and answer cards), the grade and the device are attached automatically.
- A random per-install id is used only for rate limiting.

**Server**
- `migrations/0005_user_feedback.sql`: a `user_feedback` table with status `new`/`triaged`/`done`/`wontfix` and a note.
- `server/userFeedback.ts`:
  - validates and cleans input (untrusted context is dropped, not stored);
  - rate-limits to 10 per install per hour and 200 per day;
  - saves, then emails the owner (`FEEDBACK_TO`, else `MAIL_REPLY_TO`). A mail failure doesn't lose the message.
- `functions/api/feedback.ts`: a thin wrapper (same-origin, as for the other APIs).

**Triage:** `scripts/feedback.mjs` and the **Feedback** workflow list ids, dates, kinds, screens, problem ids, statuses and notes, and set a status plus note. The queries are parameterised, and the workflow inputs reach the script only as environment variables.

**Verification**
- `tests/user-feedback.test.ts`: validation, sanitising, saving, the email (including HTML escaping), email failure, both rate limits, and the route (200/403/503/400).
- Bug caught by the browser test: problem seeds are 32-bit (up to 10 digits), but the id pattern allowed 9, so some problem ids would have been dropped. Fixed and covered by a test.
- Playwright at iPad size: Problem preselected on a card, the empty-send message, the posted payload with the problem id, "Thank you!", the sheet closes, axe 0 violations.
- `npm run check`: 23 files / 750 tests passed, and the build passed.

**Owner to-do:** set the Pages variable `FEEDBACK_TO` (or rely on `MAIL_REPLY_TO`). Known minor point: a timed Test's clock keeps running while the sheet is open.
