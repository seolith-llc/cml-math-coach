## Request (verbatim)

> add neon to the Math Coach app too

## Response

Context: the owner's CodeQuest app got neon/fluorescent code highlighting (lessons and exams). Math Coach has no code, so "neon" applies to what it emphasises.

**Decisions**
- New setting `highlight: 'neon' | 'classic'`, default **neon**; older saves migrate to neon, invalid values fall back to neon (`migrateSettings`, new case in `tests/settings.test.ts`).
- Mirrored to `<html data-hl>` by `ui/dom.applyHighlight` at start (`app.ts`) and from **Settings → Highlights** (Neon | Classic segmented control; no helper text, per the UI rule).
- Neon look (`styles.css`, end): lime highlighter on `**bold**` key words in problems and captions; glow on explanation pulses and on meaning-carrying outlines (`s-accent`, `s-s1`, `s-s2`, `s-good`); lime edge on the newest hint; print falls back to plain.
- Contrast checked: light #1c1c1e on #e4ff3a 15.1:1; dark #f5f5f7 on the lime tint 5.7–9.4:1 by surface.

**Verification**
- `npm run check`: typecheck, 753 tests (incl. the new settings case), build.
- Playwright on a production build (`vite preview`), light and dark: neon is the default, key words highlighted (compare-results topic), explanation box glows, Settings switch to Classic persists across reload, no page errors.
- First glow attempt targeted only accent shapes and was invisible: the answer boxes use the series colours; widened to s-s1/s-s2/s-good and re-checked.

**Files:** src/core/storage.ts, src/ui/dom.ts, src/app.ts, src/screens/settings.ts, src/styles.css, tests/settings.test.ts, docs/TESTING.md (H4), CLAUDE.md.

**Note:** only 5 of 10 problem families mark key words in bold, so about half the problems show the highlighter; the explanation glow applies to all.
