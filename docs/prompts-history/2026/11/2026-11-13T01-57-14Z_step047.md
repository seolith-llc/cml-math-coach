## Request (verbatim)

> add bold key words to the other problem types

## Response

**Found first**
- `prepareForSpeech` didn't remove `**` markers, so problems that already used bold were sent to the voice with asterisks (some device voices read them out). Fixed: markers are stripped before speaking (test added in `tests/answer.test.ts`). Both voices (natural and device) go through it.
- A probe over 11,760 problems (every topic × grade × level × 40 seeds) showed 16 CML topics with no bold at all: more than the "5 of 10 files" estimate, because a file with some bold still had topics without any. (The first probe run reported "all bold" because it passed the topic id instead of the topic and swallowed the errors; caught and fixed before relying on it.)

**Decisions**
- Bold the key quantities and the question's target, 1–3 per problem (e.g. "The **sum** of two numbers is **23**. One number is **3 more** … the **larger** number?"); existing capitalised conditions (BOTH, exactly ONE, DIFFERENT, NOT) bolded too.
- Never inside `speech` fields (two templates had the same phrase in `text` and `speech`; only `text` changed). Logic-puzzle clue strings are reused by the scenes, so only the question's target is bolded there.
- CogAT unchanged: its verbal items already bold their stimulus words; it isn't required to mark key words.

**Files:** src/content/generators/{counting,money,puzzles,time,word,number,family,logic,placement}.ts (~75 templates), src/voice/speech.ts, tests/keywords.test.ts (new: every CML problem has balanced, non-empty bold and none in speech), tests/{answer,family,generators,placement}.test.ts (parse the plain text), CLAUDE.md (New topic rule).

**Verification:** `npm run check` passes (802 tests). Browser on a production build, light and dark: heads-legs, logic-order, sum-difference, above-below-zero, calendar show the highlighter on the intended words; no raw asterisks; no page errors. All on-screen uses of problem text go through `rich()`; the parent email digest already strips/renders markers.
